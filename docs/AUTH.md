# 패스키를 어떻게 붙였는지 — T08 설명 문서

## 1) 무엇을 붙였나

- 과제1의 소개 페이지 전체를 **패스키(WebAuthn) 잠금**으로 덮었다.
- 비밀번호·계정·서버 없이, 소유자의 인증기(폰 생체, 기기 PIN, 보안키)만 통과한다.
- 통과 전에는 본문이 렌더되지 않고 잠금 화면만 뜬다.

## 2) 파일별 역할

| 파일 | 하는 일 |
|---|---|
| `passkey.js` | WebAuthn 호출·base64url·DER 변환·서명 검증 (공통 라이브러리) |
| `passkey-config.js` | 등록된 소유자 패스키의 **공개키 목록** — 자격증명 allowlist |
| `lock.js` | 잠금 오버레이 표시·"패스키로 들어가기" 버튼·해제 처리 |
| `setup.html` / `setup.js` | 소유자용 등록 도구 — 자격증명 생성·공개키 출력·즉석 시험 |

## 3) 등록 → 잠금 → 해제 흐름

```
setup.html ── create() ──▶ 자격증명 (비밀키는 인증기 속에, 공개키만 나옴)
                              │
                              ▼
                 공개키를 passkey-config.js에 기록
                              │
index 방문 ── lock.js 오버레이 ── get() ──▶ 인증기가 서명
                              │
                              ▼
              passkey.js가 서명을 직접 검증 ── 통과 → 페이지 표시
```

## 4) 검증에서 실제로 확인하는 것

`get()`이 돌려준 assertion을 그대로 믿지 않고, 다섯 가지를 확인한다:

1. **종류** — `clientDataJSON.type`이 `webauthn.get`인가
2. **챌린지** — 보낸 챌린지와 응답의 챌린지가 같은가 (재전송 공격 방지)
3. **출처·RP** — `clientDataJSON.origin`이 이 도메인이고, `authData` 앞 32바이트가 `sha256(rpId)`와 같은가
4. **사용자 검증** — 플래그에 UP(존재)+UV(생체·PIN 검증)가 켜져 있는가
5. **서명** — 저장해 둔 공개키로 `signature`를 WebCrypto에서 검증하는가 (ES256 우선, RS256 폴백). 카운터(`signCount`)도 읽어 복제 인증기 감지에 쓴다

전부 통과해야 잠금이 풀린다 — 자바스크립트로 흉내 낸 응답은 5번에서 반드시 끊긴다(개인키 없이는 유효한 서명을 못 만든다).

## 5) 왜 공개키를 코드에 박는가

- 서버 없는 정적 사이트라 자격증명을 저장할 DB가 없다.
- 공개키는 이름 그대로 **공개해도 안전한 값** — 비밀은 인증기 속 개인키뿐.
- 그래서 allowlist는 "배포 파일에 적힌 공개키 목록"이 된다. 등록된 패스키가 아니면 `allowCredentials` 단계에서 이미 튕긴다.

## 6) 정적 호스팅이라 지키는 것 vs 못 지키는 것

**지키는 것**

- 패스키 없는 사람은 절대 유효한 서명을 못 만든다 → 잠금 화면을 못 넘는다.
- 비밀번호가 없어서 뺏길 비밀도 없다(피싱·재사용·브루트포스가 통하지 않음).
- 인증기가 "이 도메인"에 묶인 서명만 만든다 — 다른 도메인 피싱 사이트에서는 서명이 안 나온다.

**못 지키는 것(솔직한 한계)**

- 정적 호스팅이라 페이지 소스는 누구나 받을 수 있다 → 개발자도구로 `locked` 클래스를 지우거나 스크립트를 끄면 본문 DOM은 들여다볼 수 있다. **잠금은 UX·무결성 게이트이지 비밀 유출 차단은 아니다** — 진짜 비밀 자료는 두면 안 된다.
- 공개키 목록이 파일에 박혀 있으므로, 등록 패스키를 잃어버리면 config를 고쳐 다시 배포해야 한다.
- `signCount` 클론 감지는 참고 정보라 서버 없이는 강제 수단이 제한된다.

이 한계를 알고도 "소개 페이지를 패스키로만 여는" 과제에는 적합하다 — 검증은 진짜 암호학이고, 숨길 게 아니라 잠금 자체가 시연 대상이니까.

## 7) 지원 조건

- `navigator.credentials` + `PublicKeyCredential`이 있는 브라우저(최신 크롬·엣지·사파리·파이어폭스).
- `https` 또는 `localhost`에서만 WebAuthn이 열린다 (브라우저 보안 규칙).
- Windows Hello가 없는 환경이라도 폰 QR(하이브리드 패스키)로 등록·인증할 수 있다 — 이 프로젝트는 그 경로를 그대로 쓴다.
